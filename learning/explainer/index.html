    GPS acquisition as a CAM lookup

    A simulation study asks whether a Hamming-distance-tolerant content-addressable memory (HD-CAM) can replace the correlator in GPS L1 C/A acquisition. This handbook explains the question, the algorithm, the five CAM designs, the measurements, the code, and what comes next.

    Chapter 1The research question

    A GPS receiver starts by acquiring satellites. It decides which of the 32 GPS satellites are in view, and for each one it estimates two numbers that tracking needs: the Doppler (carrier frequency offset, within ±5 kHz) and the code phase (where the 1023-chip spreading code starts inside the received samples).

    Every receiver does this with correlation. This study asks whether a different piece of hardware, a Hamming-distance-tolerant CAM, can do the same job as a memory lookup.

    What an HD-CAM is

    A content-addressable memory (CAM) stores words in rows. You present a query word, and every row compares itself against it in parallel, in one search cycle. An ordinary CAM reports exact matches. An HD-CAM reports every row whose Hamming distance to the query is at most a threshold. Each row's match line discharges in proportion to how many of its bits mismatch, and a sense amplifier compares the discharge against a tunable reference.

    The study's hardware reference is a 65 nm HD-CAM macro (Garzón et al., IEEE JSSC, 2025): 128 kbit, banks of 512 rows × 64 bits, 125 MHz, 0.19 fJ per bit per search, and a Hamming tolerance of 1 to 8 bits in a 64-bit word. The 8-of-64 figure, 12.5% of the word, is the number this whole study is measured against.

    The idea

    Store every (PRN, Doppler) replica of the C/A code, quantised to 1 bit per I and Q sample, as one CAM row. Quantise one code period of the received signal the same way and present it as the query. One search then tests every PRN and every Doppler bin at once. Code phase becomes the serial loop: slide the query window one sample at a time.

    The FFT receiver makes code phase parallel and loops over PRN and Doppler. The CAM receiver swaps the axes. That swap is the whole proposal.

    The bet

    The CAM is not an algorithmic win. Each search is an exhaustive 1-bit time-domain correlation against every row, so it performs about \(N/\log_2 N \approx 190\times\) more bit operations than an FFT search at 2046 bits per row. The bet is that an in-memory compare at sub-fJ per bit, with no data movement, beats a digital FFT ASIC by more than that factor.

    PROPOSAL.md puts one 10 ms acquisition at 36 832 searches over 2.75 Mbit: about 19 µJ and 295 µs at 8 ns per search. That number is encouraging, and it counts for nothing unless the signal can be detected at all at the tolerance silicon can provide.

    The decisive question (PROPOSAL risk 1). A 1-bit GPS sample at realistic signal levels disagrees with its own replica on almost half its bits, because the per-sample SNR is about −20 dB at 40 dB-Hz. So the threshold must sit near half the word. Silicon shows 12.5%. If the required fraction cannot be reached, the approach fails at every word width, because SNR sets the fraction, not the word length.

    3. Set-B sensitivity is more than 3 dB worse than the baseline with no cost win to pay for it.

    Chapter 7 shows that rule (ii) kills every family, the baseline included.

    Chapter 2Acquisition from first principles

    Each GPS satellite spreads its signal with its own 1023-chip C/A code, a Gold code built from two 10-stage shift registers (G1 and G2). The code repeats every 1 ms at 1.023 Mchip/s. The study samples at 1.023 MHz, one sample per chip, so one code period is 1023 complex samples. A 10 ms record holds 10 230 samples.

    The received signal for one satellite is the code, delayed by the code phase, multiplied by a carrier at the Doppler frequency, buried in noise:

    \[ r[n] = a\, c\big[(n-\tau) \bmod 1023\big]\, e^{\,j\left(2\pi f_d n / f_s + \theta\right)} + w[n], \qquad w[n] \sim \mathcal{CN}(0, 1) \]

    The study fixes noise at unit power, so \(N_0 = 1/f_s\) and the amplitude is \(a = \sqrt{(C/N_0)/f_s}\). At 40 dB-Hz that is a per-sample SNR of −20.1 dB. The signal is invisible sample by sample. Correlating 1023 samples gains 30 dB, and that is what makes it visible.

    Acquisition tests every hypothesis (PRN, Doppler bin, code phase). For each one it wipes off the carrier, multiplies by the replica code, and sums. The right hypothesis produces a peak. The figure below runs that search on a synthetic satellite with the real Gold codes.

    The search space at the study's configuration is 32 PRNs × 21 Doppler bins (−5 000 to +5 000 Hz in 500 Hz steps) × 1023 code phases: 687 456 cells. Every acquisition method is a strategy for visiting those cells.

    Chapter 3One bit per sample, and Hamming distance

    A CAM compares bits. So both the stored replica and the received query are quantised to one bit per component: the sign of I and the sign of Q. quantize_iq stores the 1023 I-signs followed by the 1023 Q-signs, so a code period becomes a 2046-bit word.

    On ±1 values, correlation and Hamming distance are the same measurement. For an \(n\)-bit word with signs \(\mathbf{s}, \mathbf{b} \in \{\pm 1\}^n\):

    \[ \operatorname{hd}(\mathbf{s}, \mathbf{b}) = \frac{n - \mathbf{s}\cdot\mathbf{b}}{2} \]

    A perfect match has distance 0. An unrelated word has distance near \(n/2 = 1023\). The code uses this identity to compute every distance as a single matrix multiply (distance_table), and a test asserts it equals bit-by-bit counting.

    Carrier phase is the catch

    Correlation takes a magnitude, so it ignores the carrier phase θ. Hamming distance cannot: a replica received in antiphase sits at distance 2046, the far end of the scale. The 1-bit classifier covers the circle with 8 phase hypotheses:

    • 4 query rotations. Multiplying by \(j\) maps \((I, Q)\) to \((-Q, I)\). On sign bits that is a swap of the two planes with one plane complemented, so a 1-bit front end can rotate a query by quarter turns with no arithmetic.
    • 2 stored phases per row, at 22.5° and 67.5°. The codebook is built offline at full precision, so it can be quantised at any starting phase. Mid-quadrant phases keep every row off the axes; a row at exactly 0° would have an all-zero Q plane that matches anything.

    The true hypothesis takes the minimum over the 8 combinations. That minimum is D_true in the study's vocabulary.

    This figure is PROPOSAL risk 1 in one picture. At useful signal levels the true row and a wrong row differ by a few tens of bits out of 2046, and both sit far above 12.5% of the word. A single look cannot separate them. The classifier needs many looks and a vote, and those cost sensitivity.

    Keeping only the sign costs about 1.96 dB of SNR against full-precision correlation (the classic 2/π hard-limiting loss). Resolving carrier phase into 8 hypotheses costs roughly another 2.5 dB, according to PROPOSAL.md.

    Chapter 4Two algorithms, one search space

    Both classifiers answer the same question with the same output: a list of PrnResult(prn, doppler_hz, code_phase). They differ in which axis of the search space they make parallel.

    The FFT reference (fft_acq.py)

    The textbook parallel code-phase search (Van Nee & Coenen, 1991). For each PRN and Doppler bin it wipes off the carrier, transforms each code period, multiplies by the conjugate spectrum of the replica, and inverse-transforms. That yields the circular correlation at all 1023 code phases at once. Power is summed non-coherently across the 10 code periods.

    code_fft[prn] = conj(FFT(replica(prn)))                 # once per PRN, offline
for prn in PRNs:                                        # serial
    for f in doppler_grid:                              # serial
        z      = samples · exp(−j2π f t)                # carrier wipe-off
        corr   = IFFT(FFT(blocks(z)) · code_fft[prn])   # all code phases at once
        grid[f, :] = Σ_blocks |corr|²                   # non-coherent sum
    f*, τ* = argmax(grid)
    if grid[f*, τ*] / second_peak(grid[f*, :]) ≥ peak_ratio:   # default 2.5; calibrated 2.0
        report(prn, f*, τ*)

    It uses full-precision complex arithmetic. In the study it is the reference: the control that every CAM family is compared against, run through the identical calibration protocol and scorer.

    The 1-bit HD-CAM classifier (hdcam_acq.py, the baseline family)

    The codebook holds one row per (PRN, Doppler bin, stored phase): 32 × 21 × 2 = 1 344 rows of 2 046 bits, 2.75 Mbit in total. The query is one code period of the record, quantised the same way.

    for prn, f, φ in PRNs × doppler_grid × {22.5°, 67.5°}:      # offline
    CAM[row] = quantize_iq(replica(prn) · exp(j(2π f t + φ)))   # 2046 bits

for start in 0 .. 9207:                     # serial: code phase (and look)
    q    = quantize_iq(samples[start : start + 1023])
    τ    = start mod 1023;   look = start // 1023
    for r in 0..3:                          # 4 quarter turns
        for row in CAM.search(rotate(q, r)):    # every (PRN, Doppler) at once
            hit[row, τ, look] = True

votes[row, τ] = number of looks with a hit               # 9 looks per code phase
survivors     = {(row, τ) : votes[row, τ] ≥ min_votes}
for each survivor: d = tightest_match(...)  # bisect the CAM threshold, ~11 searches
for prn: report the survivor with the smallest d

    A 10 ms record gives 10 230 − 1023 + 1 = 9 208 window starts. Each start is one code phase in one look (one code period). Every code phase gets at least 9 looks (n_looks = n_codes − 1). Times 4 rotations, that is 36 832 searches per acquisition.

    The decision rule, step by step

    One rule serves all five CAM families. It lives once, in CamAcqClassifier (cam_acq.py).

    1. Hit. A row matches a query when its distance is at most hd_threshold. A hypothesis is one row, so the two stored phases of a (PRN, Doppler) pair are voted on separately. Only the segmented family groups rows: its 16 sub-rows of one code period form one hypothesis.
    2. Look votes. A look votes for a cell (hypothesis, code phase) when at least min_segments of that hypothesis's rows matched in it, under any rotation. For every family except segmented, min_segments = 1.
    3. Shortlist. A cell survives when at least min_votes looks voted. The code's default is \(\lceil 9/3 \rceil = 3\); calibration picked 4 for the baseline.
    4. Rank. Each survivor gets the smallest distance any of its queries reached. On hardware that distance comes from tightest_match, which bisects the CAM threshold; in simulation it comes from the distance table.
    5. Report. For each PRN with a survivor, report the closest cell: its Doppler bin and code phase. There is no peak-to-second-peak test on the CAM side.

    Two data paths feed this rule. search_mode="cam" issues one search per query, as hardware would. search_mode="table" computes every distance at once with a GEMM, through \(\operatorname{hd} = (n - \mathbf{s}\cdot\mathbf{b})/2\). A test asserts both return the same results. The table path is the only affordable way to replay a grid of thresholds over hundreds of records.

    Why votes matter, and why they bite. A single look cannot separate the true row from chance (Figure 2). Votes add independent looks, like non-coherent integration. But a vote is a 1-bit decision per look, so it throws away the distance information that a correlator would sum. With only 9 looks in 10 ms, the vote has very little to work with. Chapter 7 shows the consequence.

    Chapter 5Five ways to arrange the CAM

    The baseline is one arrangement of the CAM. The family study (docs/CAM_FAMILY_STUDY.md) asks whether a different arrangement needs less tolerance or less hardware. Each family changes what a row holds and what a query holds. All five run the same decision rule.

    Baseline: hdcam_acq.py, OneBitHdCamClassifier

    One row per (PRN, Doppler bin, stored phase): 1 344 rows × 2 046 bits. One query per start sample, in 4 rotations: 36 832 searches. Chapters 3 and 4 describe it.

    Code-only rows: code_only_acq.py, CodeOnlyHdCamClassifier

    Rows hold the code with no carrier: 32 PRNs × 2 stored phases = 64 rows, 21× less area. The query carries the Doppler instead. Each window is wiped at each of the 21 Doppler bins before searching, so searches rise 21× to 773 472, and energy stays the same: the same bit comparisons, rearranged.

    The headline mixer, mixer="quadrant", keeps the front end 1-bit. It converts each sample's two sign bits to a 2-bit quadrant number and adds a 2-bit phase ramp mod 4, with no multiplier. Each sample takes up to 45° of rounding, which costs about 1.2 dB. mixer="exact" wipes with a full-precision NCO before quantising; it is not a 1-bit front end and is reported only as an upper bound.

    Thermometer: thermometer_acq.py, ThermometerHdCamClassifier

    I and Q are quantised to 4 levels and written in unary: level L is L ones, then zeros, in 3 bits. Hamming distance between two unary words is the absolute difference of their levels, so the CAM computes an L1 distance. Rows are 3× wider: 1 344 × 6 138 bits. Two-bit quantisation loses 0.55 dB against 1.96 dB for one bit.

    The quantiser needs a gain. It uses the RMS of the record itself (component_scale), never the simulator's noise level, which would be cheating. Because the bits inside a unary word are dependent, the chance floor is not n/2; the family measures it (about 39% of the word) and sets its threshold from the measurement.

    Segmented: segmented_acq.py, SegmentedHdCamClassifier

    Each code-period row is cut into 15 sub-rows of 128 bits (64 samples): 20 160 rows, the match-line width silicon has shown. The last 63 samples of each period are left out. One sliding 64-sample query visits every segment at every alignment: segment k at start s is segment 0 at start s − 64k, so searches stay near the baseline's (40 668). A look votes when at least min_segments = 5 of the 15 sub-rows match.

    The catch, found in phase 2: a 64-sample segment lasts 62.6 µs, so its frequency resolution is about 16 kHz. The whole ±5 kHz search fits inside one resolution cell, and every Doppler bin matches equally. The family is Doppler-blind and needs refine.py's second stage. It is scored through the table path only, because at a 39% threshold on 128 bits a quarter of all rows hit every search.

    Differential: diff_acq.py, DifferentialHdCamClassifier

    Rows and queries hold the delay-multiplied product \(x[n]\, x^*[n-L]\). The carrier phase cancels, so there are no rotations and no stored phases: 32 PRNs × 4 Doppler classes = 128 rows, one search per start, 9 106 searches, 42× less energy. Two problems were predicted before any code was written, and both held:

    1. Doppler becomes one constant phase \(2\pi f_d L / f_s\), which one bit resolves into 4 classes. Resolving 500 Hz needs a long lag; staying unambiguous over ±5 kHz needs L ≤ 102. Both cannot hold, so the family is Doppler-blind.
    2. A delay-multiply detector goes as SNR² at low SNR. At −20 dB per sample, the noise × noise penalty is about 20 dB.

    Chapter 6How the study measures

    Every number comes from the same code path for every classifier, on the same records. These rules were fixed before the runs.

    Records: gps-sdr-sim skies

    Test signals come from gps-sdr-sim, a third-party simulator vendored as a git submodule. It produces a real constellation from a real broadcast ephemeris. A seven-line patch (third_party/patches/0001-report-doppler-and-code-phase.patch) makes it print each satellite's true Doppler and code phase, so every record is labelled with ground truth. The build copies the submodule, patches the copy, and compiles there; the submodule stays clean.

    • 60 skies at 17-minute spacing: set A (20 skies, calibration) and set B (40 skies, evaluation). ScenarioBank.split() keeps them disjoint. Set B is untouched until phase 4.
    • Each sky is rescaled to 7 record-average C/N₀ values, 36 to 54 dB-Hz in 3 dB steps. A simulator record does not depend on C/N₀, so sim_cache.py runs the simulator once per sky.
    • Every classifier sees the same samples array for a record. Five families scored on five independent draws would be five experiments, not one comparison.

    C/N₀ is measured per satellite

    Path loss and the receiver antenna pattern spread one simulated sky over about 8 dB (measured: 40.2 to 48.5 dB-Hz on one sky). So the record-average C/N₀ is only the sampling design. measure_cn0_dbhz correlates the clean record with each satellite's true replica over one code period and sets \(C/N_0 = 10\log_{10}\!\left(a^2 f_s\right)\). It searches ±1 sample around the labelled code phase, because the simulator's fractional phase rounds to a sample and one sample is one chip.

    One event vocabulary (§4.1, evaluate.score_events)

    EventDefinition
    foundPRN reported with |frep − ftrue| ≤ 500 Hz (one bin) and wrapped |τrep − τtrue| ≤ 1 sample
    wrong fixPRN reported, but Doppler or code phase outside tolerance. Counts as a miss and a false alarm.
    missNot found (includes a wrong fix)
    false alarmA PRN reported that is not in the record
    • Pd = found / observations, pooled over (record, satellite) pairs and binned by per-satellite C/N₀ in 1 dB bins, with Clopper-Pearson intervals.
    • Pfa,acq = records with at least one false alarm / records. The target is 1e-2. Demonstrating 1e-4 would need about 30 000 records (rule of three), so the study does not claim it.
    • Sensitivity = the lowest C/N₀ bin with Pd ≥ 0.9, from at least 100 observations.

    Two Doppler-blind families need a second stage

    The segmented and differential families report a PRN and a code phase but cannot resolve Doppler (Chapter 5). Scored raw, every detection would be a wrong fix. refine.RefinedClassifier wraps them with DopplerRefiner, a 1-bit correlator that sweeps the 21 Doppler bins at the code phase the CAM named. It costs about 3 300× less than a full correlation search, and the study reports its cost separately because it is still a correlator.

    Calibration protocol (§4.5, phase 3)

    1. For each family, compute one distance table per set-A record (140 records).
    2. Replay a grid of (threshold, votes) settings through decide_grid, the same rule as decide, and score each with the events above.
    3. For each vote rule, take the loosest threshold whose measured Pfa,acq clears 1e-2. Among those, pick the highest pooled Pd in the 38–42 dB-Hz bins.
    4. Freeze it as a FrozenSetting in docs/calibration.json.

    The FFT reference goes through the same protocol over a peak_ratio grid. That matters: "everything at matched Pfa or it is not a comparison".

    Correction applied in phase 3. The plan asked to gate on the 95% upper bound of Pfa. With zero false alarms in \(n\) records that bound is \(3/n\) regardless of the setting: 2.1e-2 on 140 records. No setting could pass, so the gate measured the length of the run, not the design. Phase 3 gates on the measured rate and prints the bound beside every pick.

    The separation screen (§4.6, phase 1)

    Before building full classifiers, the screen measured each family's distances directly, with no decision rule. screen.py defines:

    • Dtrue: per present satellite and per look, the distance between the query at the true code phase and the true row (nearest Doppler bin, best stored phase, best rotation).
    • Dwrong: distances of every row of an absent PRN, at every start. Its mean is the measured chance floor: 997.5 ± 13.6 on 2046 bits, below 1023 because the floor is a minimum over four rotations.
    • d′, per C/N₀ bin: \[ d^\prime = \frac{\overline{D}_\text{wrong} - \overline{D}_\text{true}}{\sigma_{D_\text{wrong}}} \]
    • Required tolerance, the threshold that would catch 90% of true looks: \[ T = \frac{P_{90}\!\left(D_\text{true}\right)}{\text{word width}} \]

    What the table does not show

    • The false-alarm rate is bimodal. A setting false-alarms on nearly every record or on nearly none. Baseline: threshold 955 with 3 votes gives 1.0000; 944 with 4 votes gives 0.0071. Segmented: 53 gives 1.0000 and 50 gives 0.0000, three bits of 128. Figure 4's model shows the same cliff.
    • Phase 1's ranking did not survive. Segmented was second best on tolerance and is last on detection. The number that transferred from phase 1 was d′, not the tolerance fraction.
    • Code-only picked the baseline's exact setting. Both have 1 374 912 cells and the same chance floor, so they share a calibration grid. Its 0.164 against 0.273 is the cost of the quadrant mixer.
    • Why it fails at 40 dB-Hz. d′ is 3.01 and 3.48 in the two bins inside 38–42 dB-Hz, against 6.25 at 45 dB-Hz. Nine 1-bit looks do not separate at that d′. This is a result about the operating point: 10 ms of signal, decided by votes.

    What this does not establish. Set B is untouched, so these are calibration numbers. Pd is pooled over the band, not fitted, so sensitivity in dB is a phase 4 quantity. Pfa ≤ 1e-4 is not demonstrated.

    Prior art the study does not cite yet

    No published work applies a CAM, a TCAM or an HD-CAM to GNSS or PN-code acquisition. In-memory and analog acquisition do exist, so the novelty claim is "Hamming-tolerant CAM lookup", not "in-memory acquisition" (PROPOSAL risk 7).

    • CCSA (ISSCC 2023, Shanghai Jiao Tong University) [12]: a mixed-signal GPS acquisition accelerator with charge-domain correlation. 28 nm, 64 × 64 PE array, 114–394 TOPS/W. This is the strongest silicon baseline found, and the closest analog-correlation prior art.
    • RRAM-crossbar GPS acquisition (Lin Wei et al., J. Guangdong Univ. of Technology) [13]: code correlation on RRAM crossbars, 0.94 mW, 27.2 TOPS/W. In-memory acquisition, though a crossbar MAC rather than a CAM.
    • Trimble memory-based search (US 6,091,785 and continuations, expired) [14]: store 1 ms of signal, hold replicas in memory, compare and threshold. The conceptual ancestor of "store replicas, present a query".
    • PiC-BNN (arXiv 2026) [5]: reuses the same 65 nm HD-CAM silicon as a statistical classifier for binary neural networks. The closest published use of HD tolerance as a detector.

    The HD-CAM line of work

    • Garzón et al., IEEE Access 2022 [1]: the HD-CAM concept, simulation only (65 nm, Monte Carlo), sensing Hamming distance by match-line charge redistribution. The preprint claims tolerance of very large distances, about 60% of the pattern length. That is a simulation claim. PROPOSAL.md describes it as "a theoretical ceiling of about half the word width"; reword that.
    • Garzón et al., IEEE JSSC 2025 [2]: the 128-kbit silicon. It senses distance by match-line discharge speed, a different mechanism from [1], with the threshold programmable through bias voltages. Attribute the Veval fragility argument to this paper, not to [1].
    • Approximate CAM review (Chips, 2023) [4], from the same group.
    • Similarity search in memory more broadly: analog memristor CAMs [15], in-memory hyperdimensional computing [16], hyperdimensional associative memories [17], FeFET multi-bit CAMs [18]. A 7 nm study shows interconnect parasitics degrade wide match lines [19], which bears on PROPOSAL risk 2 (2046-bit rows).

    Four rules not visible from any single file

    • The classifier contract (acq_base.py). Public acquire() asserts the sample count and calls _acquire(). Subclasses override _acquire, never acquire. Everything downstream accepts any object with this interface.
    • A CAM family overrides hooks, not the decision. A family supplies build_codebook, row_index, query_index and query_variants, and sets n_rows and n_columns before super().__init__. Four lines map any (row, query) hit to (PRN, Doppler bin, code phase, look). A family that does not fit them needs a new index field, not a second _acquire.
    • AcqConfig is the single source of geometry. Samples per code, samples per acquisition and the Doppler grid are derived properties; nothing stores its own copy.
    • One rule, two data paths. search_mode="cam" searches query by query and measures survivors with tightest_match; search_mode="table" reads the same hits off a GEMM distance table. Tests assert they agree.

    cam_acq.pyexplorationThe shared base of every CAM family, and the one decision rule (1 066 lines).
    Interface
    • quantize_iq, rotate_quarter_turns, binomial_tail, per_look_false_alarm, hd_threshold_for_false_alarm

    • Hit to hypothesis, for every family: prn = row.prn[r]; Doppler from the row, or from the query when the row says −1; code_phase = (start − segment_offset) mod 1023; look = start // 1023.

    How it works
    • Grid: thresholds at the chance floor − σ·sd for σ in 1.5…5.0 (8 values) × votes {2, 3, 4, 6}: 32 settings; 8 peak ratios for the FFT.
    • Each record's table is replayed through decide_grid and scored with score_events.
    • Pick: per vote count the loosest threshold with measured Pfa,acq ≤ 1e-2, then the highest Pd in 38–42 dB-Hz.
    • RefinedCamCalibrator runs the Doppler second stage inside the loop without touching the refiner's cost counter.
    • FrozenSetting stores threshold, votes and ratio, not min_segments, mixer or refiner.

    ReferenceGlossary

    Acquisition
    Deciding which satellites are present and estimating each one's Doppler bin and code phase, coarsely enough to hand over to tracking.
    C/A code, PRN
    The 1023-chip Gold code each GPS satellite spreads with, repeating every 1 ms. The PRN number (1–32) names the satellite and its code.
    Code phase
    Where the code period starts inside the record, in samples (0–1022 at 1.023 MHz, where one sample is one chip).
    Doppler bin
    One of 21 carrier-frequency hypotheses from −5 000 to +5 000 Hz in 500 Hz steps.
    C/N₀
    Carrier-to-noise density in dB-Hz, measured per satellite in this study. 40 dB-Hz is a per-sample SNR of −20 dB at 1.023 MHz.
    HD-CAM
    A content-addressable memory that returns every row within a Hamming-distance threshold of the query, in one parallel search.
    Row, codebook
    A stored replica word; the codebook is all rows. The baseline row is one code period of one (PRN, Doppler bin, stored phase), 2046 bits.
    Query
    One window of the record, quantised like a row and presented to the CAM. The baseline issues one per start sample, in 4 rotations.
    Rotation, stored phase
    The two ways the classifier covers carrier phase: 4 bit-level quarter turns of the query, times 2 stored phases per row, for 8 hypotheses.
    Look
    One code period of the record. Each code phase gets 9 looks in 10 ms.
    Cell, hypothesis
    A hypothesis is the set of rows voted together (one row, except in the segmented family). A cell is a hypothesis at one code phase; votes and distances attach to cells.
    Threshold, votes
    hd_threshold: the largest distance that counts as a hit. min_votes: looks a cell needs to survive. Calibration picks both.
    Dtrue, Dwrong, d′
    Distance of the true row at the true code phase (best of 8 phase hypotheses); distances of absent-PRN rows; their separation in units of sd Dwrong.
    Tolerance fraction
    The threshold divided by the word width. The study's central number: 36–50% needed, 12.5% shown in silicon.
    Family
    One arrangement of the CAM: baseline, code-only, thermometer, segmented, differential.
    Doppler-blind
    A family that names PRN and code phase but cannot resolve Doppler (segmented, differential). It needs refine.py's second stage.
    Set A, set B
    The 20 calibration skies and the 40 evaluation skies. Set B stays untouched until phase 4.
    Found, wrong fix, miss, false alarm
    The study's event vocabulary (§4.1). A wrong fix counts as a miss and a false alarm.
    Kill rule
    One of three pre-registered conditions that end a family. Rule (ii): Pd ≥ 0.9 at 40 dB-Hz at the target false-alarm rate.
